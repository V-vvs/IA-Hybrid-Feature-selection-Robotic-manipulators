# Feature Selection for Execution Failure Classification in Robotic Manipulators

> **Paper:** "Feature selection for execution failure classification in robotic manipulators: an interpretability-oriented approach"  
> *Submitted to Pattern Recognition Letters (Springer Nature), 2026*

---

## Overview

This repository contains the full Python implementation of the hybrid feature selection framework proposed in the paper. The pipeline classifies robotic manipulator operational states (**collision**, **normal**, **obstruction**) from 6-axis force/torque sensor data, using a combination of ANOVA, ReliefF, and correlation-based filtering, validated through SHAP interpretability analysis.

**Key results:** 98.04% accuracy and F1-Macro ≈ 0.979 using only 28–47 features (up to 80% dimensionality reduction from the original 144 engineered features), across KNN, SVM, MLP, and LightGBM classifiers.

---

## Dataset

The UCI Robot Execution Failures dataset (Lopes & Camarinha-Matos, 1998) is used:  
🔗 https://archive.ics.uci.edu/dataset/138/robot+execution+failures

The dataset contains 5 sub-datasets (LP1–LP5) with force/torque time series from a Sony SRX-4CH SCARA manipulator. In this work, samples are aggregated into 3 classes: **collision**, **normal**, and **obstruction** (252 total instances).

Place the raw data files in `data/raw/` before running the pipeline.

## Execution Order

The scripts must be run in the order below. Each step generates outputs consumed by the next.

### Step 0 — Data Preprocessing and Feature Extraction
```bash
python Split_datasets.py
```
Performs the stratified 80/20 train/test split and extracts 144 statistical features (mean, std, RMS, kurtosis, entropy, peak frequency via FFT, etc.) from the 6 force/torque variables. Outputs 4 CSV files to `Preprocessed_Data/`.

> ⚠️ All preprocessing statistics (normalization, feature scores) are computed exclusively from the training partition to prevent data leakage.

---

### Step 1 — Scenario 1: Raw Temporal Features
```bash
python Scenario1.py
```
Uses the raw flattened time-series values (90 features) as input. Trains KNN, SVM, MLP, and LightGBM with Optuna (TPE sampler, 50 trials, 10-fold stratified CV). Outputs results, confusion matrices, and SHAP variable-level analysis to `ML_Results_Scenario1_*/`.

---

### Step 2 — Scenario 2: All 144 Statistical Features + SHAP
```bash
python Scenario2.py
```
Loads the best hyperparameters from Scenario 3 (no-correlation, 100% cumulative threshold combo) and retrains all models on the full 144-feature set. Generates SHAP feature rankings saved to `ML_Results_Scenario2_SHAP/SHAP_Analysis/`. The output `shap_feature_rankings.csv` is required by Scenario 4.

> **Note:** Scenario 2 intentionally loads hyperparameters from Scenario 3 to ensure cross-scenario comparability.

---

### Step 3 — Scenario 3: Grid Search (ANOVA + ReliefF + Correlation)
```bash
python Scenario3.py
```
Core contribution of the paper. Runs a full grid search over:
- **Pearson correlation threshold** ρ ∈ {0.70, 0.75, 0.80, 0.85, 0.90, 0.95, 1.0, NoCorr}
- **Cumulative importance threshold** τ_cum ∈ {0.80, 0.85, 0.90, 0.95, 1.00}

Yielding 40 feature subsets (23–144 features). Each combination trains all 4 classifiers with Optuna optimization. Results saved to `ML_Results_Scenario3_GridSearch/`.

   *This step is computationally intensive. Expected runtime: several hours depending on hardware.*

**Generate publication figures:**
```bash
python Scenario3_analyse.py
python Scenario3_best_params.py
```

---

### Step 4 — Scenario 4: SHAP-Based Feature Selection
```bash
python Scenario4.py
```
Uses the SHAP importance rankings from Scenario 2 to select features for each classifier independently, sweeping cumulative thresholds of 80%, 85%, 90%, 95%. Generates the heatmap and sensitivity figures (`fig_sc4_combined.png`).

---

### Cross-Scenario Analysis
```bash
python cross_scnarios_analysis.py
```
Generates the feature overlap comparison figure between Scenarios 3 and 4 for each classifier (Fig. 12 in the paper). Requires outputs from both Scenario 3 and Scenario 4.

---

### Supplementary Visualizations
```bash
python UMAPs.py                  # UMAP projections (Fig. 9)
python imprime_curvas.py         # Force/torque time-series (Fig. 4)
python Distribuition_Datasets.py # Class distribution (Fig. 2 & 3)
```

## Reproducibility

Full reproducibility is ensured through:

- Fixed global seed: `RANDOM_SEED = 42`
- `OMP_NUM_THREADS=1` set **before** any library import (required for LightGBM determinism)
- `PYTHONHASHSEED=42`
- LightGBM: `deterministic=True`, `force_row_wise=False`
- Optuna: `TPESampler(seed=42)`, `n_jobs=1`
- Bootstrap CI: local `numpy.random.RandomState` (never modifies global state)
- All preprocessing statistics computed from training partition only
